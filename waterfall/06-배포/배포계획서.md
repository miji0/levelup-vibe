## 2. 배포 환경

| 환경 | 용도 | 구성 |
|------|------|------|
| 로컬 | 개발·자동 테스트 | Docker `postgres:17-alpine`(`docker compose -p levelup up -d db`), 필요하면 호스트 포트 override |
| Preview | PR 확인 | Vercel Preview. **운영 DB·발송 키를 공유하지 않는다** |
| Production | 운영 | Vercel + Neon |

### 2.1 운영 환경 변수 (Production 전용)

이름만 적는다. **값은 문서·저장소·채팅에 남기지 않는다.** 비밀값 생성 명령은 `backend/.env.example`에 있다.

| 이름 | 용도 | 비고 |
|------|------|------|
| `APP_ORIGIN` | 운영 HTTPS 주소 | 없으면 API가 500(`Vercel requires an explicit HTTPS APP_ORIGIN`) |
| `DATABASE_URL` | Neon 직접 연결 | 비밀번호 포함, 노출되면 재설정 |
| `OWNER_GOOGLE_SUB` | 소유자 Google 고유 ID | 소유자는 이메일이 아니라 이 값으로 판정 |
| `OWNER_EMAIL` | 소유자 이메일 | migration에도 필요 |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Google OAuth 클라이언트 | |
| `TOKEN_ENCRYPTION_KEY`, `TOKEN_ENCRYPTION_KEY_ID` | Gmail 토큰 암호화 | 백업 키와 별도 |
| `MAIL_DELIVERY_ENABLED` | 실발송 스위치 | 현재 `true`(2026-11-27 켬). 끄려면 `false`로 바꾸고 재배포 |
| `CRON_SECRET` | 스케줄 호출 인증 | 16자 이상 무작위 |

Vercel 화면에서는 입력한 값을 다시 볼 수 없으므로, 소유자가 값을 별도로 안전하게 보관한다.

### 2.2 Google OAuth 설정

- 웹 클라이언트 1개에 **리디렉션 URI 2개**(로그인용 `https://levelup-vibe.vercel.app/api/auth/callback/google`, Gmail 연결용 callback — 경로는 README 참조)와 승인된 JavaScript 원본 `https://levelup-vibe.vercel.app`을 등록한다.
- 같은 프로젝트의 같은 클라이언트를 쓴다(클라이언트를 중복 생성하지 않는다).
- 로그인은 `openid email`만 요청하고, **처음 로그인할 때 Gmail 발송 권한을 함께 요청한다.**

### 3.1 다음 배포(코드·문서 변경)의 표준 절차

1. 브랜치 이름 `feature/<기능>` 또는 `fix/<버그>`를 제안하고 승인받는다.
2. 커밋 메시지(Conventional Commits)를 제안하고 승인받는다.
3. 앱 코드·의존성·배포 설정을 바꾸면 PR 전에 lint·테스트를 통과시킨다(README의 검사 명령). 문서만 바꾸면 `git diff --check <base>...HEAD`와 링크 확인으로 충분하다.
4. PR을 만들고 CI(`Foundation checks`)가 통과하면 소유자가 병합한다.
5. 병합 후 Vercel 배포가 READY가 되는지 확인하고, 인증 없는 API 요청이 401인지 본다.
6. DB 스키마를 바꾸는 변경은 `db/migrations`에 **새 번호 파일**을 추가하고 운영 DB에 별도로 적용한다(배포가 자동으로 적용하지 않는다). 기존 migration 파일은 수정하지 않는다.

## 4. 롤백 계획

### 4.1 롤백 기준

- 로그인이 되지 않거나 API가 계속 5xx다.
- 메일이 중복 또는 잘못 발송된다(발송을 켠 뒤).
- 비밀값이 노출됐다.

### 4.2 롤백 절차

| 상황 | 조치 |
|------|------|
| 새 배포가 고장 | Vercel 배포 목록에서 이전 READY 배포(`isRollbackCandidate`)로 롤백(Instant Rollback). 롤백은 소유자가 화면에서 실행 |
| 메일 오발송 | 즉시 `MAIL_DELIVERY_ENABLED=false`로 바꾸고 재배포 |
| 비밀값 노출 | 해당 값을 재생성하고 Vercel 값을 교체·재배포. Neon 비밀번호는 Neon에서 재설정(2026-11-27 연결 문자열 노출 시 이렇게 처리함). Google 클라이언트 비밀번호는 콘솔에서 새로 만들고 이전 것을 사용 중지 |
| 스케줄 오작동 | `vercel.json`에서 해당 schedule을 제거하는 PR을 병합하거나 `CRON_SECRET`을 교체해 호출을 막는다 |

### 4.3 데이터 롤백

migration은 되돌림 스크립트가 없다. 데이터 문제가 생기면 [운영 가이드](운영가이드.md)의 백업·복원을 쓴다. 복원 훈련은 아직 하지 않았으므로 **첫 백업 후 복원 훈련을 한 번 해야** 이 경로를 믿을 수 있다.

## 6. Google OAuth 앱 프로덕션 게시

> 근거: PRD 8.2(프로덕션 게시, 검증 제출 안 함), PRD OPEN-002, SAD 7.4.

**현재 상태(2026-11-27 완료 항목 표시).** 동의 화면이 **테스트 중**이면 Gmail refresh token이 7일 뒤 만료된다. 정기 메일을 켜기 전에 아래를 마쳤다. 요청 범위는 `openid`·`userinfo.email`(민감하지 않음)과 `gmail.send`(민감한 범위)다.

- [x] 운영 도메인에 로그인 없이 열리는 홈페이지(`/`)와 **개인정보처리방침 페이지**가 있다(확인: `/`·`/login`·`/privacy`가 로그인 없이 HTTP 200). 방침에는 수집 항목(Google 계정 이메일·고유 ID), `gmail.send` 용도(본인 계정에서 본인에게 아침 메일), 받은편지함을 읽지 않음, 토큰 암호화 보관, 연결 해제·권한 철회 방법, 문의처를 적는다.
- [x] Google 인증 플랫폼 → 브랜딩에 홈페이지·개인정보처리방침 링크·승인된 도메인(`vercel.app` 도메인이 거절되면 개인 도메인을 연결)을 입력한다. **로고는 올리지 않는다**(올리면 검증 제출 대상이 된다). 브랜딩을 저장했고 입력 값은 소유자가 Google 콘솔에서 직접 입력했다.
- [x] 대상 → [앱 게시] → 상태가 **프로덕션**으로 바뀐 것을 확인한다. 검증 제출 안내가 나와도 **제출하지 않는다.** (확인: 대상 화면 게시 상태 "프로덕션 단계", 사용자 유형 외부. 인증 센터는 브랜딩·데이터 액세스 "인증되지 않음"을 안내하지만 제출하지 않았다.)
- [x] 로그인 때 "확인되지 않은 앱" 경고에서 고급 → LevelUp(으)로 이동 → 동의 → 설정에서 "연결됨"을 확인한다. 게시 전에 받은 연결이 있으면 [다시 연결]한다.
- [x] 테스트 메일을 1회 보내 도착을 확인했다(2026-11-27 15:45 KST, Gmail 접수·받은편지함 도착).
- [ ] **8일 뒤(2026-12-05)** 테스트 메일을 다시 보내 성공하는지 확인한다(7일 만료가 없는지).
- 게시 상태를 테스트로 되돌리면 7일 만료가 다시 적용된다. 로그인·발송이 실패하면 리디렉션 URI와 환경 변수를 먼저 확인하고 게시 상태는 유지한다.
