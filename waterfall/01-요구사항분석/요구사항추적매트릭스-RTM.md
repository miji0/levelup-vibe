# 요구사항 추적 매트릭스 (RTM)

> Requirements Traceability Matrix. 실제 LevelUp SRS 초안을 기준으로 연결한다. 모든 설계·구현·실행 테스트는 미착수이며, 수용 기준 연결을 테스트 통과로 표시하지 않는다.

## 1. 목적

기획 문제·MVP·구체 정책 → SRS FR/NFR·자체 수용 기준 → UC → 후속 설계·코드·TC·실행 증빙을 추적한다. 출처와 검증 조건은 지금 연결하고 실제 존재하지 않는 설계 절·커밋·테스트 결과는 만들지 않는다.

## 3. 상태 정의

### 3.1 요구사항 상태

| 상태 | 기준 |
| --- | --- |
| 초안 | 현재 모든 요구사항. 출처·SC 작성, 소유자 검토 전 |
| 승인 | 실제 G1 대상 버전·승인 근거 기록 후 사용 |
| 변경중·보류·삭제 | 소유자의 변경 결정·사유·영향·적용 버전 연결 시 사용 |

### 3.2 매핑 상태

| 구분 | 현재 상태 |
| --- | --- |
| 출처·SC | 연결됨. 동작 검증 결과와 다름 |
| UC | 모든 FR에 흐름 연결. NFR는 관련 흐름 또는 구조 검증으로 연결 |
| 설계·구현 | 미착수. 상위 템플릿 위치는 실제 설계 참조로 계산하지 않음 |
| TC | 미작성. 05-테스트의 범용 예시는 연결한 실제 TC가 아님 |
| 실행·판정·증빙 | 미실행 / 없음. 제품 통과·승인 없음 |

## 6. 커버리지 요약

분모는 현재 첫 릴리스의 포함 요구사항 33개(기능 23 + 비기능 10)다. 이는 문서 추적 현황이며 승인된 기준선·실행률이 아니다.

| 지표 | 계산 | 현재 실적 |
| --- | --- | --- |
| 출처·수용 기준 연결 | 기획/정책과 SC가 있는 요구사항 / 33 | 33 / 33 = 100% — 문서 연결만 의미 |
| 기능 UC 연결 | UC가 연결된 기능 요구사항 / 23 | 23 / 23 = 100% — 시나리오 작성만 의미 |
| 설계 매핑률 | 실제 설계 참조가 있는 요구사항 / 33 | 0 / 33 = 0% |
| 구현 매핑률 | 실제 코드/커밋 참조가 있는 요구사항 / 33 | 0 / 33 = 0% |
| 테스트 매핑률 | 작성된 실제 TC가 연결된 요구사항 / 33 | 0 / 33 = 0% |
| 수용 기준 검증 완료율 | 필수 기준을 실제 검증한 요구사항 / 33 | 0 / 33 = 0% |
| TC 실행률·통과율 | 실제 실행 TC 기준 | 산정 불가 — 작성·실행한 제품 TC 없음 |

상위 범위는 MVP 9개, PRD AC 20개, 구체 BP 36개 모두 역추적 표에 연결되어 있다. 합의되지 않은 미결을 해소하거나 테스트를 통과했다는 뜻은 아니다.

## 7. 미매핑 항목 관리

### 7.1 미매핑 항목 목록

| 요구사항 ID | 미매핑 단계·사유 | 담당자 | 목표 해결 시점 |
| --- | --- | --- | --- |
| FR-001~023, NFR-001~010 | 실제 시스템·상세 설계 없음 | 구현·설계 담당 — 지정 필요 | G2/G3 검토 전 단계별 연결 |
| FR-001~023, NFR-001~010 | 코드·후보 빌드 없음 | 구현 담당 | G4 구현 인계 전 |
| FR-001~023, NFR-001~010 | 실제 TC·실행 증빙 없음 | 구현·검증 담당 | TC 연결은 G4 전, 판정·증빙은 G5 전 |
| 미결 영향 요구사항 | DEC-001~008, ISSUE-001의 구체 값·방법 미확정 | SRS 부록 C의 담당자 | 각 결정 시점. 특히 DEC-006은 SRS 승인 전 |

### 7.2 미매핑 항목 관리 규칙

단계별 실제 자료가 생길 때 해당 행에 설계 절·코드/PR/커밋·TC·결과 보고서 위치를 넣는다. 파일 존재만으로 매핑 완료로 계산하지 않는다. 상위 DEC와 해당 FR/NFR·UC를 함께 갱신하며 미결을 임의의 제품 기본값으로 바꾸지 않는다.

### 7.3 단계별 확인 기준

| 단계 | 확인할 기준 |
| --- | --- |
| G1 요구사항→설계 | 상위 범위와 요구사항·출처·SC·미결 조건 검토, 소유자 승인 근거 연결 |
| G2 시스템 설계 | 실제 시스템·DB·API·UI 설계에서 해당 요구사항 연결 |
| G3 상세 설계 | 구현 단위 흐름·상태·예외·필요한 결정 연결 |
| G4 구현→테스트 | 대상 커밋·빌드·실제 TC와 각 SC 연결 |
| G5 테스트→배포 | 실행 판정·증빙·미충족/예외 처리·소유자 판단 연결 |

현재 G0·G1 승인 기록은 없다. [검토 체크리스트](../08-검토/단계별검토-체크리스트.md)의 작성 예시를 실제 승인으로 사용하지 않는다.

## 8. RTM 갱신 절차

### 8.1 갱신 주기

| 이벤트 | 갱신 항목 | 담당 |
| --- | --- | --- |
| 기획·정책·요구사항 변경 | MVP/BP/AC 출처, FR/NFR·SC·UC·영향 범위 | 소유자 판단 후 작성·구현 담당 |
| 설계 작성 | 실제 설계 위치와 설계 매핑률 | 설계 담당 |
| 구현·후보 빌드 준비 | 코드/PR/커밋·대상 버전 | 구현 담당 |
| 테스트 설계·실행 | 실제 TC·판정·실행 증빙·대상 빌드 | 검증 담당 |
| 단계 검토 | 미결·승인 기록과 해당 단계 커버리지 | 소유자·해당 작업 담당 |

별도의 PM·BA·QA 조직을 가정하지 않으며 동일인이 역할을 맡을 수 있다. 정기 점검 주기·일정은 DEC-005에서 정한다.

### 8.2 변경 영향 분석 체크리스트

- [ ] 변경된 기획·정책·FR/NFR·SC와 현재 릴리스 범위를 확인한다.
- [ ] 관련 UC와 실제 존재하는 설계·구현·TC에 미치는 영향을 기록한다.
- [ ] 구독 삭제·발송 경계·개인 상태·외부 AI 데이터 경계를 확인한다.
- [ ] 미결 담당·기한·판단 근거와 실제 승인 버전을 연결한다.
- [ ] 실제 매핑 수와 커버리지를 다시 계산한다.
