## 1. 관리 규칙

### 1.1 작성 기준

- 하나의 TC는 하나의 수용 기준(AC)을 대표한다. AC 하나에 여러 확인 항목이 있으면 한 TC의 기대 결과에 나열하고, 매핑 표에서 항목별 근거를 따로 적는다.
- 기대 결과는 PRD 9절 문구를 그대로 따른다. TC에서 기준을 넓히거나 줄이지 않는다.
- 자동 테스트가 없는 확인 항목은 "자동 단언 없음"으로 표시한다. 사람이 확인했다는 기록이 없으면 통과가 아니다.

### 1.2 TC-ID 규칙

| 접두사 | 유형 | 예 |
|--------|------|----|
| TC-FN-영역-번호 | 수용 기준 기능 검증 | TC-FN-AUTH-001 |
| TC-SC-영역-번호 | 보안 검증 | TC-SC-NET-001 |
| TC-OP-영역-번호 | 운영 기반 검증 | TC-OP-BKP-001 |
| TC-CP-영역-번호 | 화면·기기 호환성 | TC-CP-UI-001 |

영역: AUTH 인증, COL 수집·중복·기준, SUB 구독 등록·삭제, READ 목록·읽음, BRF 브리핑, MAIL 발송, RPT 리포트 분석, MOD 모듈 경계, MOB 모바일, NET 네트워크, CRED 자격증명, BKP 백업, UI 화면.

### 1.3 상태

| 상태 | 사용 기준 |
|------|-----------|
| PASS | 기대 결과 전부를 이번 빌드에서 실행한 자동 테스트가 확인했다 |
| FAIL | 실행했으나 기대와 달랐다. 결함을 등록한다 |
| BLOCKED | 외부 환경(실제 Google·실기기 등) 없이는 실행할 수 없다 |
| SKIPPED | 테스트가 있으나 환경 조건 때문에 건너뛰었다 |
| NOT RUN | 이번 빌드에서 실행하지 않았거나 자동 단언이 없다. 일부만 자동 근거가 있으면 "부분 근거"로 적는다 |

### 1.4 실행 증빙의 종류

| 표기 | 뜻 |
|------|----|
| **[실행]** | 2026-11-27 이 빌드에서 직접 실행한 pytest 188개(DB 포함) 또는 vitest 10개 |
| **[기록]** | 04 인계서·구현진행현황에 적힌 Playwright E2E 16개 통과 기록. 이번에 재실행하지 않았다. 결과가 기록과 같다고 가정하지 않는다 |
| **[없음]** | 대응하는 자동 테스트나 기록이 없다 |
