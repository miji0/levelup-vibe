## 1. 문서 개요

### 1.1 목적

PRD 9절의 수용 기준 AC-001~020을 검증하는 방법, 환경, 종료 기준을 정한다. 테스트 케이스는 [테스트케이스](테스트케이스.md), 실행 결과는 [테스트결과보고서](테스트결과보고서.md)에 둔다.

### 1.2 범위

- **대상 시스템:** `apps/web`(Next.js), `backend/src/levelup`(FastAPI·수집·메일), `db/migrations`(001~003)
- **대상 빌드:** `5973b5a` + 미커밋 작업 트리. 후보 커밋은 아직 없다.
- **테스트 기간:** 2026-11-27 로컬 1차. 7일 시범 운영은 별도다.

## 2. 테스트 전략

### 2.1 레벨별 전략

| 레벨 | 대상 | 도구 | 자동화 | 현재 규모 |
|------|------|------|--------|-----------|
| 백엔드 단위·통합 | 수집·날짜 판정·중복·메일 예약·인증·SSRF·백업 | pytest + PostgreSQL 17 | 전부 | 188개 |
| 웹 단위 | API 응답 처리, 리포트 요청문·URL 검증 | vitest | 전부 | 10개 |
| 정적 검사 | 린트·포맷·타입 | ruff, mypy, eslint, prettier, tsc | 전부 | — |
| E2E | 로그인·구독·수집·글 상태·리포트 인계·화면 | Playwright (Chromium 1280 / WebKit 390) | 전부 | 16개(8 시나리오 × 2) |
| 수동·실환경 | 실제 Google·Gmail·iPhone Safari·7일 시범 운영 | 사람 확인 | 없음 | 미실행 |

**원칙**

- 날짜·수집·중복·발송 불명은 가짜 시계와 저장된 RSS/HTML fixture, 가짜 Gmail 전송으로 검증한다. 실제 계정으로 메일을 보내지 않는다.
- DB 테스트는 `TEST_DATABASE_URL`이 있어야 실행된다. 없으면 80개가 건너뛰어지므로 전체 통과로 보지 않는다.
- 중복·초기 기준·누락 날짜·시간대 경계·늦은 발견·수집 실패·발송 재시도를 반드시 포함한다(AGENTS.md).

### 2.2 유형별 전략

| 유형 | 적용 |
|------|------|
| 기능 | AC-001~020을 TC로 풀어 자동 테스트에 매핑한다 |
| 보안 | 소유자 판정, CSRF, OAuth state·PKCE, 내부 네트워크 차단(SSRF), 토큰 암호화. OWASP ZAP 등 스캐너는 첫 버전에서 채택하지 않았다 |
| 호환성 | Mac Chrome(Chromium 1280px), iPhone Safari(WebKit 390px 에뮬레이션). 실기기는 인수 전 조건 |
| 접근성 | 키보드 조작, 44px 누르는 영역, 포커스 복귀를 E2E가 일부 확인. WCAG 전체 체크리스트는 채택하지 않음 |
| 성능 | 임의 수치 목표를 두지 않는다. 수집 한도(15초·1,000항목·5MiB)는 단위 테스트로 확인하고 운영 응답 시간은 시범 운영에서 관찰한다 |
| UX·사용성 | 소유자 본인 7일 시범 운영의 정성 평가. SUS·NPS 없음 |

## 4. 테스트 환경

### 4.1 로컬 환경

| 항목 | 값 |
|------|----|
| OS·런타임 | macOS, Python 3.12(uv), Node.js 24, pnpm |
| DB | `postgres:17-alpine`, `docker compose -p levelup up -d db` |
| DB 연결 | `TEST_DATABASE_URL=postgresql+psycopg://levelup:levelup@127.0.0.1:<포트>/levelup` |
| 외부 연동 | Google은 가짜 공급자와 실제 RSA 서명 token, Gmail은 가짜 전송, 피드는 fixture |

> **포트 충돌 기록(2026-11-27):** 이 PC에서는 5432를 다른 프로젝트의 `apolo-postgres` 컨테이너가 쓰고 있어 `compose.yaml` 그대로는 `levelup-db-1`이 기동하지 못했다(`port is already allocated`). 다른 컨테이너는 건드리지 않고, 저장소 밖의 임시 override로 호스트 포트만 54329로 바꿔 띄웠다. `compose.yaml`은 수정하지 않았다. 5432가 비어 있는 환경에서는 README 명령을 그대로 쓴다.

테스트 DB는 UUID 임시 스키마를 만들고 종료 시 지운다. 운영·공용 DB를 지정하지 않는다.

### 4.2 테스트 데이터

| 구분 | 방법 |
|------|------|
| 글·피드 | 저장된 RSS/Atom/등록 어댑터 fixture |
| 계정 | 테스트 전용 고정 소유자 sub와 이메일, 서버 설정으로 주입 |
| 시간 | 주입한 가짜 시계(KST 경계, 7일, 08:20 마감) |
| 기본 출처 5곳 | 2026-11-27 읽기 전용 실표본 결과는 04 구현진행현황. 원문은 저장하지 않는다 |

실제 비밀값·토큰은 테스트 문서와 저장소에 넣지 않는다.

### 4.3 외부 환경 의존 항목

| 항목 | 현재 |
|------|------|
| 실제 Google 로그인·운영 callback | 미실행 |
| 실제 Gmail 접수·도착 | 미실행 (`MAIL_DELIVERY_ENABLED=false` 기본) |
| Vercel Services·Schedules, Neon 무료 한도 | 미실행 |
| 클라우드 백업·복원 훈련 | 미실행 |
| iPhone Safari 실기기 | 미실행 |

### 4.4 실행 명령

```sh
docker compose -p levelup up -d db
export TEST_DATABASE_URL=postgresql+psycopg://levelup:levelup@127.0.0.1:5432/levelup
backend/.venv/bin/ruff check backend
backend/.venv/bin/ruff format --check backend
backend/.venv/bin/mypy --config-file backend/pyproject.toml backend/src
backend/.venv/bin/pytest backend/tests -q -rs
pnpm --dir apps/web lint
pnpm --dir apps/web typecheck
pnpm --dir apps/web test
pnpm --dir apps/web test:e2e --workers=1
```

`-rs`는 건너뛴 테스트의 사유를 보여 준다. 결과 보고에는 "통과 n, 건너뜀 m"을 모두 적는다.

### 4.5 편집 시 자동 점검(훅)

`.claude/settings.json`의 PostToolUse 훅이 Claude Code가 파일을 편집할 때마다 [post-edit-check.sh](../../.claude/hooks/post-edit-check.sh)를 실행한다.

| 편집한 파일 | 훅이 실행하는 것 |
|-------------|------------------|
| `backend/**/*.py` | ruff check, ruff format --check, mypy, DB 없는 pytest(단위 테스트) |
| `apps/web/**/*.ts(x)`, `tests/e2e/*.ts` | pnpm lint, typecheck, vitest |
| 그 밖의 파일(문서 등) | 아무것도 하지 않음 |

실패하면 exit 2로 끝나고 오류 내용이 Claude에게 전달된다. 훅은 `TEST_DATABASE_URL`을 비워 실행하므로 DB 테스트는 포함하지 않는다. **훅 통과는 G5 판정 근거가 아니다.** 전체 검증은 4.4의 명령으로 한다.

## 5. 진입·종료 기준

### 5.1 진입 기준 (G4 → 테스트)

| 기준 | 현재 |
|------|------|
| 검증할 commit·빌드가 식별됨 | 미충족 — 커밋 없이 작업 트리 상태로 실행 |
| 격리 DB 환경 | 충족 (Docker 로컬) |
| 두 언어의 정적 검사·테스트 결과 | 충족 (결과보고서 2장) |
| RTM에 실제 코드·TC 연결 | 미충족 — RTM v0.12는 TC "미작성" 상태. 본 TC 반영 시 갱신 필요 |
| 인계서 4장 체크리스트 | 미판정 |

### 5.2 결함 심각도

| 등급 | 정의 |
|------|------|
| S1 | 중복·누락 메일 발송, 소유자 외 접근, 데이터 손실, 내부 네트워크 접근 |
| S2 | 주요 기능 불가(우회 없음), 날짜·대상 판정 오류 |
| S3 | 우회 가능한 기능·화면 오류 |
| S4 | 문구·간격 등 사용에 영향 없는 문제 |

### 5.3 G5 종료 기준 (제안 — 소유자 승인 필요)

| 기준 | 제안 | 판정 근거 |
|------|------|-----------|
| 필수 수용 기준 | AC-001~020 **전부** PASS. 이 목록에서 예외를 허용하지 않는다(PRD 10절 "모든 수용 기준을 충족한 뒤 출시 판단") | 결과보고서 8장 |
| 실행률·통과율 | 실행률 100%, 통과율 100% (건너뜀·차단·미실행 0건) | 결과보고서 1.1 |
| 출시 차단 결함 | S1·S2 미해결 0건 | 결함 목록 |
| 실환경 | 실제 Google 로그인, 실제 Gmail 접수·도착, iPhone Safari, 백업 복원 훈련 확인 | 수동 기록 |
| 시범 운영 | 7일 운영 후 수집 누락·중복 발송을 테스트 글·발송 기록과 대조해 해결 | 시범 운영 기록 |
| 승인 | 소유자가 계획서 버전과 일시를 기록 | 승인 기록 |

위 수치는 제안이다. 소유자가 승인하기 전에는 확정 기준이 아니다.

## 6. 일정·역할

고정 일정을 두지 않는다. PRD 10절에 따라 수용 기준을 검증한 뒤 7일 시범 운영을 하고 소유자가 출시를 판단한다. 실제 수행 일자는 결과보고서에 기록한다.

| 활동 | 담당 |
|------|------|
| 테스트 설계·자동 테스트 실행·보고 | Claude Code (소유자 요청 시) |
| 실환경·실기기 확인, G5 승인, 출시 판단 | 소유자 |

## 9. UX·접근성 계획

- 화면 완료는 AGENTS.md 기준을 따른다: **Figma 대조 → 차이 수정 → 다크/라이트 × 데스크톱 1280px/모바일 390px 확인.** 비교나 viewport·테마 확인이 빠지면 "디자인 미검증"으로 보고한다.
- Figma는 읽기 전용으로 비교하고 수정하려면 먼저 소유자 승인을 받는다.
- 접근성은 키보드 조작·포커스 복귀·44px 영역·오류 안내(role=alert)를 E2E로 일부 확인한다. WCAG 2.1 AA 전체 체크리스트는 첫 버전에서 채택하지 않았다.
- 사용성은 소유자 7일 시범 운영 후 탐색 부담, 아침 읽기, 요청문 준비 편의를 정성으로 검토한다(PRD 10절).
- 현재 화면별 Figma 대조 기록은 [04 인계서 3.4](../04-구현/구현-테스트-인계서.md#34-공통-화면로그인-ux-보완-2026-11-27)와 [구현 진행 현황](../04-구현/구현진행현황.md)에 있다. 이번 문서 작업에서 화면을 새로 확인하지 않았다.

## 부록

### A. 자동화 전략

회귀 대상은 전부 자동화되어 있다. 자동 단언이 없는 AC(AC-013·014·015, AC-004의 일부)는 [테스트케이스 3장](테스트케이스.md#3-ac--기존-테스트문서-매핑)에 표시했다. 기존 테스트 코드는 이번 작업에서 수정하지 않았다. 신규 테스트 추가는 소유자 승인 후 별도로 진행한다.
